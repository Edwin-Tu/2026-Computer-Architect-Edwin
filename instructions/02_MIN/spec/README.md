## 1. 正式語意

- **指令名稱：** MIN（32-bit signed minimum）。
- **語意公式：** `rd = min_signed(rs1, rs2)`；比較採二補數有號整數。
- **運算元與定義域：** `rs1`、`rs2` 各提供一個 32-bit 位元模式；有號解讀範圍均為 `[-2147483648, 2147483647]`，全部輸入組合皆有定義。
- **結果範圍：** `[-2147483648, 2147483647]`；結果等於兩個輸入中較小者的完整 32-bit 位元模式。
- **相等條件：** 兩輸入相等時，寫回共同值。本文件的虛擬碼選取 `rs2`，不影響結果。
- **邊界條件：** 含零時仍按有號大小比較；負數小於零與正數。兩者為負數時選數值較小者，例如 `-20 < -10`。`INT32_MIN` 小於其餘所有合法值；`INT32_MAX` 與其他值比較時選另一值，相等時保留共同值。
- **溢位處理：** MIN 只比較與選值，不計算差值、和或乘積，因此不產生算術溢位；不需要飽和或回繞處理。
- **寫回規則：** 先取得兩個來源的舊值，再寫回 `rd`，所以 `rd` 可與任一來源相同。沿用 RISC-V 暫存器規則，讀取 `x0` 得到 0，寫入 `x0` 的結果丟棄；其他暫存器不變。

`0xFFFFFFFF` 在本規格中代表 `-1`，所以與 `0` 比較時應選 `0xFFFFFFFF`，不能使用無號大小比較。也不能用可能溢位的 32-bit `rs1 - rs2` 的符號，直接代替有號比較。

## 2. 虛擬碼

```text
function signed32(bits):
    u = bits AND 0xFFFFFFFF
    if u >= 0x80000000:
        return u - 0x100000000
    return u

function MIN(registers, rd, rs1, rs2):
    a_bits = 0 if rs1 == 0 else registers[rs1]  // 先讀取來源舊值
    b_bits = 0 if rs2 == 0 else registers[rs2]
    if signed32(a_bits) < signed32(b_bits):
        result_bits = a_bits
    else:
        result_bits = b_bits
    if rd != 0:
        registers[rd] = result_bits
```

此處 `signed32` 的減法是以足夠寬的數學整數定義位元解讀，不是讓 MIN 執行一個可能溢位的 32-bit 減法。
在以上虛擬碼中，`rs1`、`rs2`、`rd` 是暫存器編號（0–31）；公式中的同名符號則表示對應來源／目的的 32-bit 值。`registers[0]` 的架構值固定為 0。

## 4. RV32IM baseline 與語意一致性

採用既有 [min_branch.S](../rv32im/min_branch.S)，不更動核心：

```asm
# a0 = rs1，a1 = rs2，a0 = 結果
min_branch:
    blt  a0, a1, .Lbranch_done
    addi a0, a1, 0
.Lbranch_done:
    jalr zero, 0(ra)
```

- `rs1 < rs2`：有號 `blt` 跳到返回，保留 `a0`（rs1）。
- `rs1 >= rs2`：不跳躍，以 `addi` 複製 rs2 至 a0；相等時仍得到共同值。
- `addi a0, a1, 0` 只複製位元，`jalr` 返回。因此 baseline 與上面的比較、選值語意一致。

## 5. 5 Whys：為什麼必須使用有號比較？

1. 為什麼不能用無號比較？因為題目定義允許負整數，`-1` 應小於 0。
2. 為什麼相同位元會有不同大小關係？因為 `0xFFFFFFFF` 有號解讀為 -1，無號解讀為 4294967295。
3. 為什麼 baseline 使用 `blt`？因為它比較有號值，與 C 的 `int32_t` 比較一致。
4. 為什麼還要測極值？因為只用小正數無法發現無號比較或差值溢位造成的錯誤。
5. 為什麼這個選擇可核對？原案例 `(0, -1)` 及 `(INT32_MAX, INT32_MIN)` 的預期值分別為 -1 與 INT32_MIN，可由表格和保存機器碼執行比對。
