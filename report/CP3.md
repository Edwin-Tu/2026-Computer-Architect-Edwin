# CP3 — MIN 自訂指令規格、編碼與指令數比較

## 1. 本次目標

定義兩個 32-bit 有號整數取小的 MIN 自訂指令，提供語意、虛擬碼、含邊界值的範例、完整機器碼及欄位說明，並在相同輸入與計數範圍下比較 C baseline、RV32IM Branch、Branchless 與自訂 MIN 的指令數。

## 2. 設計內容

### 2.1 語意規格

| 項目 | 定義 |
|---|---|
| 指令名稱 | MIN |
| 組合語言介面 | `min rd, rs1, rs2` |
| 語意公式 | `rd = min_signed(rs1, rs2)` |
| 來源 | rs1、rs2 各提供一個 32-bit 二補數有號整數 |
| 定義域 | 兩來源均為 −2147483648 至 2147483647，全部輸入組合皆有定義 |
| 結果範圍 | −2147483648 至 2147483647，結果為較小來源的完整 32-bit 位元模式 |
| 相等時 | 寫回共同值；本報告的虛擬碼選 rs2，不影響結果 |
| 算術溢位 | 只比較與選值，不計算輸入的差、和或乘積，因此不產生算術溢位 |

零、正負混合、兩個負數及上下極值都依有號大小比較，不做額外飽和。例如 `0xFFFFFFFF` 代表 −1，應小於 0；不能改用無號比較，也不能只看可能溢位的 32-bit 減法結果來判斷大小。`INT32_MIN` 小於所有其他合法值，與自身比較仍回傳自身。

先讀取兩個來源的舊值，再寫回目的，所以 `rd` 可以與 `rs1` 或 `rs2` 重疊。讀取 `x0` 得 0，寫入 `x0` 的結果丟棄；其他暫存器不變。寫回保留被選來源的全部 32 位元。

### 2.2 虛擬碼

```text
function signed32(bits):
    u = bits AND 0xFFFFFFFF
    if u >= 0x80000000:
        return u - 0x100000000
    return u

function MIN(registers, rd, rs1, rs2):
    a_bits = 0 if rs1 == 0 else registers[rs1]
    b_bits = 0 if rs2 == 0 else registers[rs2]
    if signed32(a_bits) < signed32(b_bits):
        result_bits = a_bits
    else:
        result_bits = b_bits
    if rd != 0:
        registers[rd] = result_bits
```

此處 `rd`、`rs1`、`rs2` 是暫存器編號 0–31；語意公式中的同名符號則表示其數值。來源都是合法 32-bit 位元模式，並在目的寫回前讀取。`signed32` 使用足夠寬的數學整數定義有號解讀，其減法不是 MIN 內部的 32-bit 算術操作。

### 2.3 範例與預期結果

以下以正負混合、相等及極值為三類主要範例，另補充零與負數以區分有號和無號比較：

| rs1 | rs2 | 預期 rd | 覆蓋情況 |
|---:|---:|---:|---|
| 3 | -2 | -2 | 正負混合，選負數；結果位元為 0xFFFFFFFE |
| 5 | 5 | 5 | 相等；結果位元為 0x00000005 |
| 0 | -1 | -1 | 零與負數；結果位元為 0xFFFFFFFF |
| 2147483647 | -2147483648 | -2147483648 | INT32_MAX／INT32_MIN 邊界；結果位元為 0x80000000 |

第一個範例若把負數誤當無號值，會錯選 3；最後一個範例則可檢查以溢位差值誤判大小的問題。兩者為負數時也使用相同規則，例如 `min(-10,-20)=-20`。

### 2.4 MIN 技術說明與計數範圍

以下四個版本使用相同介面：`a0`、`a1` 傳入來源，`a0` 回傳結果。軟體 baseline 採 RV32IM／ILP32；實際使用的機器指令都屬 RV32I。

**C baseline** 以固定寬度的有號型別表達正確行為：

```c
int32_t min_s32(int32_t rs1, int32_t rs2)
{
    return (rs1 < rs2) ? rs1 : rs2;
}
```

C 原始碼沒有固定機器指令數。本報告採既有 GCC 15.2.0、`-O2` 編譯產物，其函式本體如下：

```asm
min_s32:
    bge  a0, a1, .Lc_copy
    addi a1, a0, 0
.Lc_copy:
    addi a0, a1, 0
    jalr x0, 0(ra)
```

若 `a0 < a1`，不跳躍而執行全部 4 條；否則跳過第一個 `addi`，執行 3 條。此為特定編譯產物，不代表所有編譯器都會生成同樣程式。

**Branch** 利用第一個來源可能已是答案，減少條件路徑中的複製：

```asm
min_branch:
    blt  a0, a1, .Lb_done
    addi a0, a1, 0
.Lb_done:
    jalr x0, 0(ra)
```

有號 `blt` 成立時保留 `a0`，含返回只執行 2 條；否則複製 `a1`，含返回執行 3 條。相等時複製共同值，因此與 MIN 語意一致。

**Branchless** 將比較結果轉成遮罩，再以位元運算選值：

```asm
min_branchless:
    slt  t0, a0, a1
    sub  t0, x0, t0
    xor  t1, a0, a1
    and  t1, t1, t0
    xor  a0, a1, t1
    jalr x0, 0(ra)
```

`slt` 產生 0／1，`sub` 將其轉為全零／全一遮罩，最後選出 `a1`／`a0`。每次含返回固定執行 6 條，沒有條件分支，但會使用 `t0`、`t1`。消除分支不表示指令數或執行時間一定較少。

**自訂 MIN** 將比較與選值定義為一條指令：

```asm
min_custom:
    min  a0, a0, a1
    jalr x0, 0(ra)
```

核心固定 1 條，含返回固定 2 條。此片段為設計預期，尚未將自訂 opcode 加入工具鏈或處理器，不能當作已執行的機器碼結果。

### 2.5 R-type 欄位與機器碼

採 R-type 格式，六個欄位寬度合計 32 位：

```text
31       25 24    20 19    15 14  12 11     7 6        0
+-----------+--------+--------+-------+--------+----------+
|  funct7   |  rs2   |  rs1   |funct3 |   rd   |  opcode  |
+-----------+--------+--------+-------+--------+----------+
```

| 欄位 | 位元範圍 | 寬度 | 本報告的值或用途 |
|---|---|---:|---|
| funct7 | [31:25] | 7 | 0000000 |
| rs2 | [24:20] | 5 | 第二來源暫存器編號 |
| rs1 | [19:15] | 5 | 第一來源暫存器編號 |
| funct3 | [14:12] | 3 | 000 |
| rd | [11:7] | 5 | 目的暫存器編號 |
| opcode | [6:0] | 7 | 0001011，即 custom-0／0x0B |

`opcode=0x0B` 為課程固定格式。下列編碼採目前小組使用的 `funct7=0000000`、`funct3=000`；教師正式分配或核准來源尚未核實，因此這兩個值是本報告的編碼前提，不能視為已取得教師確認。若正式分配不同，須同步重新編碼與反解。

三組具體暫存器配置為 `(rd,rs1,rs2)=(x10,x10,x11)`、`(x12,x13,x14)`、`(x15,x16,x17)`：

| Assembly | 二進位（funct7 rs2 rs1 funct3 rd opcode） | Hex |
|---|---|---|
| min x10,x10,x11 | 0000000 01011 01010 000 01010 0001011 | 0x00B5050B |
| min x12,x13,x14 | 0000000 01110 01101 000 01100 0001011 | 0x00E6860B |
| min x15,x16,x17 | 0000000 10001 10000 000 01111 0001011 | 0x0118078B |

第一筆可令 `x10=3`、`x11=-2`，執行後 `x10=-2`；第二筆令 `x13=x14=5`，得到 `x12=5`；第三筆令 `x16=INT32_MAX`、`x17=INT32_MIN`，得到 `x15=INT32_MIN`。指令字只包含暫存器編號，不包含這些執行前數值。

編碼公式與第一筆代入：

```text
word = (funct7 << 25) | (rs2 << 20) | (rs1 << 15)
     | (funct3 << 12) | (rd << 7) | opcode

word = (0 << 25) | (11 << 20) | (10 << 15)
     | (0 << 12) | (10 << 7) | 0x0B
     = 0x00B5050B
```

反解依序取 `(word>>25)&0x7F`、`(word>>20)&0x1F`、`(word>>15)&0x1F`、`(word>>12)&0x7`、`(word>>7)&0x1F`、`word&0x7F`：

| 指令字 | funct7 | rs2 | rs1 | funct3 | rd | opcode |
|---|---:|---:|---:|---:|---:|---:|
| 0x00B5050B | 0 | 11 | 10 | 0 | 10 | 11 |
| 0x00E6860B | 0 | 14 | 13 | 0 | 12 | 11 |
| 0x0118078B | 0 | 17 | 16 | 0 | 15 | 11 |

三筆均還原出原 Assembly 的暫存器與操作欄位。這項核對證明欄位組合一致，不等於處理器已執行自訂 MIN。

## 3. 結果與分析

### 3.1 測量條件與方法

前三個軟體版本的比較數據採用 2026-10-23 已保存的來源重建結果，並非本次重寫報告重新編譯所得。工具與範圍如下：

- 編譯器：xPack GNU RISC-V Embedded GCC 15.2.0；反組譯工具：GNU Binutils 2.45。
- 目標：`-march=rv32im -mabi=ilp32`；最佳化：`-O2`。
- 其他主要旗標：`-ffreestanding -fno-builtin -fno-pic -fno-pie -nostdlib`；連結固定文字區起點 `0x10000`，停用 relax。
- 執行及計數：Python RV32I 子集合直譯器 v1.2.1，逐條執行連結後的 ELF32 機器碼。它不模擬 pipeline、cache 或 cycle，亦不是 Ripes、Spike、QEMU 或實體硬體。
- 靜態數：指定函式內實際機器指令的條數，偽指令 `mv`、`ret` 分別展開為 `addi`、`jalr` 後計數。
- 動態數：下表 14 筆輸入各執行一次的指令總次數。各版本排除呼叫端、參數準備及測試框架；核心欄排除返回，函式欄包含每次一條 `jalr` 返回。條件分支不包含 `jalr`。

### 3.3 指令數比較表

| 版本 | 核心靜態 | 函式靜態含返回 | 核心動態14筆 | 函式動態14筆含返回 | 動態條件分支14筆 | 數據性質 |
|---|---:|---:|---:|---:|---:|---|
| C baseline（編譯後 min_s32） | 3 | 4 | 32 | 46 | 14 | 保存 ELF 直譯計數 |
| Branch（min_branch） | 2 | 3 | 24 | 38 | 14 | 保存 ELF 直譯計數 |
| Branchless（min_branchless） | 5 | 6 | 70 | 84 | 0 | 保存 ELF 直譯計數 |
| 自訂 MIN | 1 | 2 | 14 | 28 | 0 | 設計預期，未執行自訂 opcode |

14 筆中有 4 筆 `rs1 < rs2`、10 筆不成立，因此：

- C：`4×4 + 10×3 = 46`；其 `bge` 有 10 次 taken。
- Branch：`4×2 + 10×3 = 38`；其 `blt` 有 4 次 taken。
- Branchless：`14×6 = 84`，條件分支為 0。
- 自訂 MIN：含返回為 `14×2 = 28`，核心為 `14×1 = 14`，均為設計預期。

核心動態數分別將函式總數扣除 14 條共同返回，得到 32、24、70、14。靜態數則每個版本只扣除一條返回，不應把靜態數乘上測資數量當成有分支版本的動態數。

### 3.4 正確性驗證與結果限制

保存重建紀錄中，C、Branch、Branchless 三函式各通過 5,199 筆：原 14 筆、33 個值的 33×33 網格 1,089 筆，以及固定種子 20261018 的隨機 4,096 筆。預期答案使用 Python 數學整數的 `min(a,b)`，輸入限制為有號 32-bit。額外以 `INT32_MIN`、`INT32_MIN+1`、−1、0、1、`INT32_MAX−1`、`INT32_MAX` 的 7×7 組合核對，三函式各 49／49 通過。資料可能重複，不代表所有 2^64 個輸入對窮舉。

本表的動態比較只使用原 14 筆，不使用全部 5,199 筆總計。保存的 22／22 流程回歸包含 mock、fixture 與歷史機器碼重播，也不是 22 次真正編譯。這些為既有驗證紀錄，不列為本次新測量。

在含返回的相同範圍，C → Branch 指令減少率為 `(46−38)/46 = 17.39%`；Branch → 自訂 MIN 的設計預期為 `(38−28)/38 = 26.32%`。若只看核心，Branch → MIN 為 `(24−14)/24 = 41.67%`。不同分母必須分開說明。

CPU 執行時間的評估關係為 `Instruction Count × CPI × Clock Cycle Time`。本次只有指令數，未量測 CPI、時脈或 cycle，因此上述百分比不能當作執行時間加速比。Branchless 的固定指令數較多，是否能因分支行為受益也不能由本資料判定。自訂 MIN 的硬體延遲與實際執行效能仍未驗證。

### 3.5 設計決策的 5 Whys

1. **為什麼提出 MIN？** 同一批 14 筆輸入，Branch 核心需 24 條，自訂 MIN 設計預期只需 14 條。
2. **為什麼可以減少？** 將有號比較與條件式選值合併為單一操作。
3. **為什麼保持正確？** 比較來源舊值，再選取原輸入位元，與兩條 Branch 路徑及邊界範例一致。
4. **為什麼不直接稱為更快？** 指令數沒有包含 CPI 與自訂操作可能改變的時脈成本。
5. **為什麼本次只比較指令數？** CP3 的要求是指令規格、編碼與指令數比較，未要求 cycle 量測；因此結論限於相同輸入與範圍下的指令數。

## 4. 遭遇的問題與解法

編碼整理時曾把 `funct7` 位元範圍誤寫為 `32:25`，第三筆 Hex 誤植為 `0x0118178B`。修正為 `31:25` 與 `0x0118078B` 後，依六個欄位逐一反解，確認總寬度 32 位、暫存器編號及 `funct3=000` 均一致。這也說明機器碼不能只看十六進位外觀，必須同時核對二進位分段與欄位值。

另一個問題是由 C 編譯的 `min_s32` 與另一份同名 Assembly 函式容易混淆。本報告直接列出用於比較的 C 編譯產物與三條 Branch 指令，固定比較對象；另份 Assembly 的 14 筆路徑推算雖同樣為 38，仍不能據此宣稱它完成保存 C 函式的 5,199／49 筆驗證。

## 5. 白話說明

MIN 指令的功能就是從兩個整數中選出比較小的數字。例如輸入 5 和 9，結果是 5；輸入 -5 和 9，結果則是 -5。因為 MIN 使用有號整數比較，所以必須正確判斷負數，不能直接使用無號比較。這條指令只需要比較並選擇其中一個數值，不必進行加減運算，因此不會因為計算而產生溢位。最後再將結果寫入指定暫存器。
