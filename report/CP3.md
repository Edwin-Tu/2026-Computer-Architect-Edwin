# CP3 — MIN：工作二語意規格與測試範例

本文交付林佳宏負責的工作二。全組最終 CP3 還需由工作三加入指定編碼與機器碼、工作四加入完整比較與個人貢獻聲明；本文不代表已繳交。內容以提供的 main ZIP 為基底，未採用其他 dev ZIP 的草稿。

## 1. 本次目標

將既有 32-bit 有號 MIN 整理成明確的語意、虛擬碼、測試向量及 RV32IM baseline 對照。

## 2. 設計內容

### 2.1 語意規格

`rd = min_signed(rs1, rs2)`。兩個輸入均為 32-bit 二補數有號整數，定義域與結果範圍皆為 `[-2147483648, 2147483647]`。相等時寫回共同值；零、正負混合及極值都依有號大小比較，不做特殊飽和。MIN 只比較與選值，不計算輸入差值，因此沒有算術溢位。

完整來源值讀取、`rd` 重疊與 `x0` 寫回規則，以及虛擬碼、七組測試向量、baseline 片段與指令數，見[工作二正式規格](../instructions/02_MIN/spec/README.md)。該文件列出的七筆範例包含相等、零、負數與上下極值，超過至少三筆、含一筆邊界的要求。

### 2.2 虛擬碼與範例

```text
a = signed32(rs1 的來源舊值)
b = signed32(rs2 的來源舊值)
result = rs1 的舊位元模式 if a < b else rs2 的舊位元模式
if rd 不是 x0:
    將 result 的 32 個位元寫回 rd
```

| rs1 | rs2 | 預期 rd | 覆蓋情況 |
|---:|---:|---:|---|
| 3 | -2 | -2 | 正負混合 |
| 5 | 5 | 5 | 相等 |
| 0 | -1 | -1 | 零及有號比較 |
| 2147483647 | -2147483648 | -2147483648 | 32-bit 上下極值 |

### 2.3 baseline 與設計理由

既有 baseline 以有號 `blt` 選路徑，不跳時用 `addi` 複製第二個輸入，最後以 `jalr` 返回。靜態核心／函式指令數為 2／3；原 14 筆測資的動態路徑推算為 24／38。推算範圍不含呼叫端及測試框架，函式數包含返回。[規格中的 baseline 段落](../instructions/02_MIN/spec/README.md#4-rv32im-baseline-與語意一致性)附原碼、計數表及有號比較的 5 Whys。

## 4. 遭遇的問題與解法

本次 AI 協助檢查發現，保存 ELF 的 `min_s32` 是由 C 編譯而來，而目前另有同名 `min_s32.S`；若只看符號名稱，容易把兩份來源的證據混用。因此改以明確的 `min_branch` 作對照，核對 ELF 雜湊、目前 Branch 原碼與快照的一致性，以及保存的指令形狀，不把執行舊 ELF 寫成重新編譯。目前檢查仍是 RV32I 子集合直譯，不宣稱完整處理器認證。

## 5. 白話說明

MIN 就像比較兩張寫有整數的卡片，選出較小的數。負數也要按大小比較，例如 -2 比 3 小。兩數相等就保留共同值。它不把兩數相減，所以遇到最大或最小整數，也不會因減法超出範圍而選錯。
