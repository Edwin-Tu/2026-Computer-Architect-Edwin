## 1. 本次目標

## 2. 設計內容

### 2.1 語意規格

`rd = min_signed(rs1, rs2)`。兩個輸入均為 32-bit 二補數有號整數，定義域與結果範圍皆為 `[-2147483648, 2147483647]`。相等時寫回共同值；零、正負混合及極值都依有號大小比較，不做特殊飽和。MIN 只比較與選值，不計算輸入差值，因此沒有算術溢位。

完整來源值讀取、`rd` 重疊與 `x0` 寫回規則，以及虛擬碼、七組測試向量、baseline 片段與指令數，見[工作二正式規格](../instructions/MIN/README.md)。該文件列出的七筆範例包含相等、零、負數與上下極值，超過至少三筆、含一筆邊界的要求。

### 2.2 虛擬碼與範例

```text
a = signed32(rs1 的來源舊值)
b = signed32(rs2 的來源舊值)
result = rs1 的舊位元模式 if a < b else rs2 的舊位元模式
if rd 不是 x0:
    將 result 的 32 個位元寫回 rd
```

| rs1 | rs2 | 預期 rd | 覆蓋情況 |
|---:|---:|---:|---|
| 3 | -2 | -2 | 正負混合 |
| 5 | 5 | 5 | 相等 |
| 0 | -1 | -1 | 零及有號比較 |
| 2147483647 | -2147483648 | -2147483648 | 32-bit 上下極值 |

### 2.3 baseline 與設計理由

既有 baseline 以有號 `blt` 選路徑，不跳時用 `addi` 複製第二個輸入，最後以 `jalr` 返回。靜態核心／函式指令數為 2／3；原 14 筆測資的動態路徑推算為 24／38。推算範圍不含呼叫端及測試框架，函式數包含返回。[規格中的 baseline 段落](../instructions/MIN/README.md#4-rv32im-baseline-與語意一致性)附原碼與計數表；來源、暫存器規則與計數範圍見下一節。

### 2.4 MIN 技術說明與計數範圍

以下是我這份工作二需要能解釋的技術內容，由既有規格整理，是否已能獨立說明仍待我本人確認。

MIN 必須採有號比較，因為同一位元模式的有號與無號大小不同。例如 `0xFFFFFFFF` 以 signed 32-bit 解讀為 -1，與0比較時應選 -1。正負混合時選負數；兩個負數要選數值較小者，例如 -20小於-10。兩數相等時寫回共同值，選取哪個來源不改變結果。

`INT32_MIN=-2147483648` 是最小合法值，與其他合法值比較時選它；`INT32_MAX=2147483647` 與較小值比較時選另一值，兩個最大值相等則仍回傳最大值。MIN 只比較與選取輸入本身，結果一定是原輸入之一，不計算可能溢位的32-bit差值，因此不產生算術溢位。不能用截斷後減法的符號直接代替有號比較。

`rs1`、`rs2` 是來源暫存器編號，`rd` 是目的編號；公式則用它們代表來源值與寫回值。操作先讀兩個來源舊值，再比較並寫回，所以 `rd=rs1` 或 `rd=rs2` 都不會提早破壞輸入。讀 `x0` 得到0，`rd=x0` 時結果丟棄，其他暫存器保持不變。

C 原始碼本身沒有固定的機器指令數，數字必須對應實際編譯產物、函式及範圍。本工作二採 Branch Assembly 對照：靜態是不同機器指令的條數，核心2條，包含返回為3條；動態是指定輸入實際走過的路徑，原14例中4例taken、10例not-taken，所以核心為 `4×1+10×2=24`，包含每次返回為38。CP2另保存C編譯函式的靜態4條／原14例動態46條，那是不同來源，不能因符號同名 `min_s32` 就混用。所有數字均排除呼叫端與測試框架，不能直接視為時間或週期加速。

## 4. 遭遇的問題與解法

本次 AI 協助檢查發現，保存 ELF 的 `min_s32` 是由 C 編譯而來，而目前另有同名 `min_s32.S`；若只看符號名稱，容易把兩份來源的證據混用。因此改以明確的 `min_branch` 作對照，核對 ELF 雜湊、目前 Branch 原碼與快照的一致性，以及保存的指令形狀，不把執行舊 ELF 寫成重新編譯。目前檢查仍是 RV32I 子集合直譯，不宣稱完整處理器認證。

### 4.2 5 Whys：目錄調整後，文件操作指令為何失效？

1. **為什麼照 README 操作會失敗？** 因為命令仍指向已不存在的 `instructions/02_MIN/`，目前實際位置已是 `src/`。
2. **為什麼程式搬好了，命令卻仍指向舊位置？** 因為路徑不只存在於程式或連結，也散落在多份 README 的命令與目錄敘述；第五筆搬遷後仍有未同步的使用入口。

## 5. 白話說明

MIN 就像比較兩張寫有整數的卡片，選出較小的數。負數也要按大小比較，例如 -2 比 3 小。兩數相等就保留共同值。它不把兩數相減，所以遇到最大或最小整數，也不會因減法超出範圍而選錯。
