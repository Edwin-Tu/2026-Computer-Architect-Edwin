## 2. 設計內容

### 2.1 語意規格

<<<<<<< HEAD:instructions/02_MIN/report/CP3.md
- **指令名稱：** `MIN`
- **語意：** `rd = min(rs1, rs2)`，比較採 32-bit 二補數有號整數。
- **運算元與定義域：**二元；`rs1`、`rs2` 各為任意 32-bit 位元模式，解讀為 `[-2^31, 2^31−1]`。
- **結果範圍：**`[-2^31, 2^31−1]`，寫回較小的有號運算元。
- **邊界與溢位：**此操作只比較與選擇，不做加減乘除，因此不會產生算術溢位。若兩運算元相等，寫回共同值。

形式化表示：

```text
s1 = signed32(rs1)
s2 = signed32(rs2)
rd = rs1, if s1 < s2
     rs2, otherwise
```

### 2.2 虛擬碼

```text
function MIN(rs1, rs2):
    if signed32(rs1) < signed32(rs2):
        return rs1
    else:
        return rs2
```

相等時走 `else`，但回傳值仍與 `rs1` 相同。

### 2.3 指令介面與編碼欄位

預定組語介面：

```asm
min rd, rs1, rs2
```

依課程統一規格採 R-type、`custom-0` opcode。依最新公告，MIN 使用 `funct7=0000000`、`funct3=000`。

| 欄位 | 位元 | 值／意義 |
|---|---:|---|
| `funct7` | `[31:25]` | `0000000` |
| `rs2` | `[24:20]` | 第二個來源暫存器 |
| `rs1` | `[19:15]` | 第一個來源暫存器 |
| `funct3` | `[14:12]` | `000` |
| `rd` | `[11:7]` | 目的暫存器 |
| `opcode` | `[6:0]` | `0001011` (`0x0B`) |

欄位排列：

```text

+-----------+--------+--------+-------+--------+----------+
|  funct7   |  rs2   |  rs1   |funct3 |   rd   |  opcode  |
+-----------+--------+--------+-------+--------+----------+
```

### 2.4 三個語意範例與機器碼欄位

每個範例指定一組目的與來源暫存器。R-type 編碼指定暫存器與操作，不包含當次輸入數值；輸入值由執行前寫入這些暫存器。

| 範例 | 暫存器配置 `(rd, rs1, rs2)` | 輸入 `(rs1, rs2)` | 預期結果 `rd` | 說明 |
|---|---|---:|---:|---|
| 1 | `(a0=x10, a0=x10, a1=x11)` | `(3, -2)` | `-2` | 正負數，有號比較 |
| 2 | `(a2=x12, a3=x13, a4=x14)` | `(-5, -5)` | `-5` | 相等情況 |
| 3 | `(a5=x15, a6=x16, a7=x17)` | `(2147483647, -2147483648)` | `-2147483648` | 32-bit 有號上下界 |

各暫存器配置對應的完整機器碼如下。三筆編碼都使用 `funct7=0000000`、`funct3=000`：

```text
範例1：0000000 01011 01010 000 01010 0001011 = 0x00B5050B
範例2：0000000 01110 01101 000 01100 0001011 = 0x00E6860B
範例3：0000000 10001 10000 000 01111 0001011 = 0x0118078B
```

以範例 1 為例，代入零值後：

```text
word = (0 << 25) | (11 << 20) | (10 << 15)
     | (0 << 12) | (10 << 7) | 0x0B
     = 0x00B5050B
```

範例 2、3 依相同欄位公式，分別得到 `0x00E6860B`、`0x0118078B`。這些是指令字，不含測試輸入值；輸入值由執行前寫入所列暫存器。

### 2.5 標準 RV32IM baseline 與自訂指令片段

標準分支版本使用有號 `blt`，並以 `addi` 選擇 `rs2`；自訂 MIN 將比較與選擇合併成單一指令。以下函式範圍都包含返回指令，方便對照 CP2 的函式本體統計。

```asm
# 標準 RV32IM baseline；a0=rs1、a1=rs2、a0=結果
min_branch:
    blt  a0, a1, .Ldone
    addi a0, a1, 0
.Ldone:
    jalr x0, 0(ra)

# 提案中的自訂 MIN；使用 funct7=0000000、funct3=000
min_custom:
    min  a0, a0, a1
    jalr x0, 0(ra)
```

自訂指令尚未加入目前工具鏈或處理器，以上 `min` 是規格中的助記符，不代表現有 GNU assembler 已可組譯。比較是靜態／動態指令數，不是 cycle 或實際執行時間測量。

## 3. 結果與分析

CP2 保存的 `min_branch` 統計涵蓋 CP1 原始 14 組輸入：靜態 3 條、動態 38 條、條件分支 14 次，其中 taken 4 次。以下自訂 MIN 數字是依指令語意推算，不是實際執行自訂 opcode 的模擬結果。

| 計數範圍 | RV32IM branch baseline | 提案 MIN | 計數方式 |
|---|---:|---:|---|
| 核心運算靜態指令（不含返回） | 2 | 1 | 靜態：函式指令列數 |
| 函式靜態指令（含返回） | 3 | 2 | 靜態：含 `jalr` |
| 核心運算動態指令（14 組） | 24 | 14 | 動態：各組實際經過的函式路徑 |
| 函式動態指令（14 組，含返回） | 38 | 28 | 動態：核心運算加每次一次 `jalr` |
| 條件分支（14 組） | 14 | 0 | 動態：不含 `jalr` 返回 |

Baseline 核心運算的 24 條為 `4 × 1 + 10 × 2`：4 組 taken 路徑只執行 `blt`，另外 10 組還執行 `addi`。提案 MIN 每組固定 1 條核心指令，因此核心運算指令數依這 14 組測資由 24 降為 14；連同相同的返回指令，函式總數由 38 降為 28。這是指令數比較，不能據此推論 cycle 或執行時間加速。

### 3.1 5 Whys：為什麼提案把比較與選擇合成 MIN？

1. **為什麼提出自訂 MIN？** 依現有 14 組輸入，branch baseline 核心執行 24 條，提案 MIN 預計執行 14 條。
2. **為什麼可減少核心指令？** 標準程式以 `blt` 判斷，再視路徑執行 `addi`；自訂指令直接寫回較小運算元。
3. **為什麼單一指令能完成？** 規格把有號比較和二選一結果寫回定義成一個操作；硬體可用比較器控制結果選擇。
4. **為什麼不把指令數減少直接說成加速？** 指令數沒有描述自訂操作的資料路徑延遲，也沒有量到時脈或 cycle。
5. **為什麼本次只比較指令數？** CP3 規定本次不要求 cycle 數，pipeline 尚未教授；因此報告範圍限於靜態／動態指令數。

### 2.4 MIN 技術說明與計數範圍

在工作二中，我主要確認 MIN 指令的有號整數比較規則。MIN 會比較 rs1 與 rs2 的 32-bit 數值，並將較小的值寫入 rd。例如 rs1 為 -5、rs2 為 9 時，結果應為 -5。如果使用無號比較，負數的位元表示可能被判斷成很大的正數，造成結果錯誤。

另外，MIN 是從兩個輸入值中選擇其中一個，不需要透過減法結果判斷大小，因此不會產生算術溢位。當 rd 為 x0 時，寫入不會改變 x0 的值；當 rd 與來源暫存器重疊時，則必須確保比較使用的是寫回前的來源值。

我也理解靜態指令數與動態指令數的差別：靜態是指定統計範圍內、偽指令展開後的機器指令條數；動態則是指定輸入執行時真正經過的指令次數，因此會受到分支結果影響。兩者都須說明是否包含返回、呼叫端與測試框架。

上述為本人本次確認採用的理解文字，不宣稱教師已驗證個人理解。極值、相等與暫存器完整定義仍以第2.1節及正式規格為準；C原始碼沒有固定機器指令數。本文Branch核心／含返回的靜態數2／3、原14例動態24／38，與CP2保存C編譯函式的4／46是不同來源，不因函式符號同名而混用，也不直接代表週期或時間加速。

## 5. 白話說明

MIN 指令的功能就是從兩個整數中選出比較小的數字。例如輸入 5 和 9，結果是 5；輸入 -5 和 9，結果則是 -5。因為 MIN 使用有號整數比較，所以必須正確判斷負數，不能直接使用無號比較。這條指令只需要比較並選擇其中一個數值，不必進行加減運算，因此不會因為計算而產生溢位。最後再將結果寫入指定暫存器。
