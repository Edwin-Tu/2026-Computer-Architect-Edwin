## 2. 設計內容

### 2.1 語意規格

`rd = min_signed(rs1, rs2)`。兩個輸入均為 32-bit 二補數有號整數，定義域與結果範圍皆為 `[-2147483648, 2147483647]`。相等時寫回共同值；零、正負混合及極值都依有號大小比較，不做特殊飽和。MIN 只比較與選值，不計算輸入差值，因此沒有算術溢位。

完整來源值讀取、`rd` 重疊與 `x0` 寫回規則，以及虛擬碼、七組測試向量、baseline 片段與指令數，見[工作二正式規格](../instructions/MIN/README.md)。該文件列出的七筆範例包含相等、零、負數與上下極值，超過至少三筆、含一筆邊界的要求。

### 2.2 虛擬碼與範例

```text
a = signed32(rs1 的來源舊值)
b = signed32(rs2 的來源舊值)
result = rs1 的舊位元模式 if a < b else rs2 的舊位元模式
if rd 不是 x0:
    將 result 的 32 個位元寫回 rd
```

| rs1 | rs2 | 預期 rd | 覆蓋情況 |
|---:|---:|---:|---|
| 3 | -2 | -2 | 正負混合 |
| 5 | 5 | 5 | 相等 |
| 0 | -1 | -1 | 零及有號比較 |
| 2147483647 | -2147483648 | -2147483648 | 32-bit 上下極值 |

### 2.3 baseline 與設計理由

既有 baseline 以有號 `blt` 選路徑，不跳時用 `addi` 複製第二個輸入，最後以 `jalr` 返回。靜態核心／函式指令數為 2／3；原 14 筆測資的動態路徑推算為 24／38。推算範圍不含呼叫端及測試框架，函式數包含返回。[規格中的 baseline 段落](../instructions/MIN/README.md#4-rv32im-baseline-與語意一致性)附原碼與計數表；有號比較的 5 Whys 見下一節。

### 2.4 5 Whys：為什麼必須使用有號比較？

以下整理既有規格中的推理鏈，依據為教師有號語意、原始測資與保存 baseline；不將其當作本人已獨立推導或已通過理解驗證的證明。

1. 為什麼不能用無號比較？因為題目定義允許負整數，`-1` 應小於 0。
2. 為什麼相同位元會有不同大小關係？因為 `0xFFFFFFFF` 有號解讀為 -1，無號解讀為 4294967295。
3. 為什麼 baseline 使用 `blt`？因為它比較有號值，與 C 的 `int32_t` 比較一致。
4. 為什麼還要測極值？因為只用小正數無法發現無號比較或差值溢位造成的錯誤。
5. 為什麼這個選擇可核對？原案例 `(0, -1)` 及 `(INT32_MAX, INT32_MIN)` 的預期值分別為 -1 與 INT32_MIN，可由表格和保存機器碼執行比對。

## 5. 白話說明

MIN 就像比較兩張寫有整數的卡片，選出較小的數。負數也要按大小比較，例如 -2 比 3 小。兩數相等就保留共同值。它不把兩數相減，所以遇到最大或最小整數，也不會因減法超出範圍而選錯。
